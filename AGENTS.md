# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

## Durable product direction

- Current MVP is mobile-first at the experience layer, with the macOS application improving in parallel from the same React/domain code. Keep the scope lean: secure unlock, AI-assisted capture, review/confirm, and reliable ledger updates come before broad analytics, production cloud sync, or app-store distribution.
- The WeChat mini-program is a separate daily capture/review runtime, not a repackaged Tauri application. Share domain contracts, money rules, evidence, Markdown structures, and design tokens; use a dependency-light native WXML/JS shell for the MVP, put secrets and AI/ASR/OCR orchestration behind a BFF, and preserve the immutable parse → review → explicit confirm boundary. Do not reintroduce Taro until React compatibility, production dependency audit, package budget, and real-device performance all pass their gates.
- Develop the WeChat mini-program milestone by milestone with tests written before implementation. Every milestone requires an adversarial review covering careless users, hostile inputs, unreliable networks, hallucinating models, tampered clients, and compliance review; every discovered defect must first become a failing regression test before it is fixed.
- Mobile and WeChat mini-program development/smoke tests may use DeepSeek as the semantic provider, but only through a local-development or staging BFF whose credential comes from the server process environment or secret store. Never compile a DeepSeek key into an app, mini-program bundle, public runtime config, fixture, log, or repository. Keep provider output behind exact-evidence validation and the same pending-review/explicit-confirm boundary; Codex CLI remains desktop-demo-only.
- Mobile is the primary daily-use surface; macOS remains the stronger setup, bulk-review, backup, and recovery surface until native mobile packaging and device QA are complete.
- Visual language follows the supplied low-saturation grey/lilac dashboard reference with rounded cards, charcoal primary surfaces, lime status accents, and fine line charts.
- Treat `folio-v2-mobile.png` and `folio-v2-desktop.png` as the frontend visual source of truth. Preserve their page anatomy, card hierarchy, density, spacing, typography, and visual rhythm; future features should replace or extend only the affected component or state instead of redesigning whole pages.
- High-risk money actions must always use a parse → review → explicit confirm flow; never mutate assets directly from voice input.
- Product modules: overview, assets, cashflow, allocation planning, financial reminders, and an AI assistant for voice/file ingestion.
- Preserve the current lightweight upward-line logo concept; brand exploration should only add a restrained purple accent.
- Preferred generated avatar directions are a cute adult female virtual character or a polished pet companion.
- First production data phase should support manual entry, voice, screenshots/PDF, Markdown/plain text, CSV/TSV/XLSX, and Feishu Sheet/Base import before attempting bank connectivity.
- During the customer-demo phase, use the signed-in local Codex CLI through a direct no-shell Tauri bridge for semantic classification. Apple speech recognition converts audio to text on device; PDF/image text is extracted locally before Codex; structured Folio Markdown remains deterministic. Never describe Codex CLI as accepting raw microphone audio.
- The primary customer-demo artifact is the standalone Tauri macOS `.app`/`.dmg`, not a Vite development URL. Run the demo readiness check before presentations; commercial distribution must replace local CLI account coupling with an approved production API integration.
- Feishu Sheet/Base, Excel, and Numbers may enter through explicit user paste as tab-separated cells; never request background clipboard access, and release the raw pasted text after the review draft is created.
- The system of record must be an auditable, immutable ledger with explicit reconciliation and confirmation states.
- Final selected brand assets: the upward chart logo with thick rounded lime strokes and a short parallel purple accent separated from the green rise by about one purple-stroke width; charcoal-grey cat avatar with lime collar and purple tag.
