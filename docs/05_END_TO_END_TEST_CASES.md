# Folio 端到端测试用例

更新：2026-08-14  
状态：持续执行；每个版本在 `docs/06_ACCEPTANCE_RESULTS.md` 记录结果。

## A. 干净系统与保险库

### A-01 首次启动无 Mock

前置：删除专用测试保险库，不触碰用户其他保险库。

步骤：

1. 启动正式本地模式。
2. 创建名为“Folio 虚构验收”的新保险库。
3. 使用测试应用密码解锁。
4. 检查总览、资产、流水、提醒、规划和 AI 收件箱。

预期：

- 账户、余额、流水、事项、持仓和 AI 草稿均为零；
- 页面明确显示本机 SQLCipher 模式；
- 不出现 Demo 固定数据；
- 数据库不是普通 SQLite 明文文件。

### A-02 空库重启

步骤：锁定、退出、重新启动并用密码解锁。

预期：仍为空库；没有因 UI 初始化写入数据。

## B. AI Provider

### B-01 环境变量发现

前置：仅设置 `OPENAI_API_KEY` 或 `FOLIO_OPENAI_API_KEY`。

预期：

- 设置页显示“已检测到环境变量”；
- 前端、日志、数据库和命令响应中没有 Key；
- App 不枚举或显示其他环境变量。

### B-02 未授权外发

步骤：取消本次外部模型授权后请求解析。

预期：Rust 命令拒绝；没有网络调用、草稿或账本写入。

### B-03 连接测试

步骤：明确同意发送固定的非财务探针。

预期：返回 `connected`、Provider ID 和模型名；不返回 API Key。

### B-04 结构化抽取

输入：`2026-07-30 建行消费368.00元，购买日用品。`

预期：

- 返回一条 `transaction` 事实；
- `amountText` 保持 `368.00元`；
- `evidenceQuote` 是输入中的连续原文；
- 结果停留在待核对层。

### B-05 幻觉证据

构造模型响应，其 evidenceQuote 不在原文。

预期：Rust 安全拒绝整次抽取；账本无变化。

### B-06 网络与凭据故障

覆盖：无 Key、401、403、429、超时、5xx、无效 JSON、拒绝、输出截断。

预期：返回脱敏错误；不记录原始财务文本；账本无变化。

## C. Markdown 冷启动注入

### C-01 文件选择与来源证据

输入：`docs/demo/Folio_冷启动全量演示数据.md` 的副本。

预期：

- 计算来源 SHA-256；
- 原件二进制和完整路径不写数据库；
- 解析结果带章节/字符范围或页码证据；
- 识别为明确的 `fictional_data: true` 测试集。

### C-02 多记录拆分

预期至少识别：

- 9 个账户；
- 7 个账户内持仓；
- 收入、支出、转账、退款、费用等多类流水；
- 租金、保险、到期、还款、定投、闲置资金和法律事项；
- 一份长期规划；
- 应隔离的模糊、跨币种、重复和冲突数据。

### C-03 依赖排序

预期：账户先于持仓，账户和持仓先于相关流水/操作，事项和规划最后应用。缺少依赖的候选不能绕过到正式写入。

### C-04 未确认不写入

步骤：完成解析但关闭核对页。

预期：正式账户和余额仍为零；AI 收件箱保留待核对草稿和来源证据。

### C-05 分组确认与对账

步骤：依次确认账户、持仓、流水、事项和规划。

预期：

- CNY 账户净额为 `2314864.17`；
- 投资账户持仓合计 `386400.00`，不重复计入净资产；
- 银行理财账户持仓合计 `180000.00`，不重复计入净资产；
- USD 账户不在缺少汇率时并入 CNY 总额；
- 转账一出一入且不进入收入/支出汇总；
- 信用卡和房贷保持负债方向。

### C-06 重复注入

步骤：再次选择同一内容、改名后再次选择、复制粘贴同一正文。

预期：来源指纹命中重复；不得增加第二份账户、流水或余额。

### C-07 模糊与冲突

覆盖：

- “昨天花了几百元”；
- 跨币种转账但无汇率；
- 持仓市值与账户余额不一致；
- 同一外部流水号金额不同；
- 法律事项缺少日期或金额。

预期：进入需补充/冲突，不得自动确认。

## D. 领域数据正确性

### D-01 金额精度

覆盖：0.01、999999999.99、负债、退款、超两位小数、指数写法、空值。

预期：只接受合法十进制定点金额；正式存储为整数最小货币单位。

### D-02 持仓不重复计入

预期：账户余额是净资产事实；持仓只做账户内部分解。

### D-03 更正与冲销

预期：原记录不可变；更正追加补偿事件；重试幂等。

### D-04 周期事项

预期：完成本期保留 occurrence 历史，并从原始锚点推进下一期。

### D-05 保险数据

预期：保单现金价值可作为持仓；保费、分红、续期和犹豫期分别成为可核对事实；受益人等敏感字段只进加密备注，不进通知。

### D-06 法律/诉讼

预期：案件节点进入自定义事项；诉讼费只有明确账户、金额和日期后才可成为流水；案件金额不自动计入资产或负债。

## E. 持久化、恢复与隐私

### E-01 重启持久化

确认数据后锁定并重启。

预期：余额、记录数、来源和状态一致。

### E-02 加密备份恢复

预期：恢复为新保险库；记录数、余额、外键、来源哈希一致；Touch ID 默认关闭。

### E-03 错误密钥与篡改

预期：错误密码、错误 DEK、篡改备份和普通 SQLite 打开均失败。

### E-04 仓库与构建隐私

预期：Git、`dist`、`.app`、DMG、日志和截图中没有 API Key、真实财务数据、数据库、备份或完整本地路径。

## F. QQ 邮箱信用卡流水

### F-01 安全配置

步骤：选择一个已存在的信用卡账户，填写 QQ 邮箱、IMAP 授权码、`INBOX`、发件人域名和主题关键词。

预期：

- 数据库没有密码/授权码字段；
- 授权码只进入 macOS Keychain；
- 状态接口只返回脱敏邮箱地址；
- 停用后删除 Keychain 授权码并停止拉取。

### F-02 只读连接

预期：

- TLS 连接 `imap.qq.com:993`；
- 使用 `EXAMINE`，不使用可写 `SELECT`；
- 不删除、不移动、不发送、不标已读；
- 登录、证书、文件夹或网络错误均脱敏并失败关闭。

### F-03 邮件头白名单

预期：先取 `From/Subject`；只有精确发件人域名与主题关键词命中后才取正文。伪造后缀域名不得命中。

### F-04 多笔日结邮件

输入：一封包含 `128.35` 与 `46.80` 两笔消费的虚构邮件。

预期：

- 生成 2 个 `email_transaction` 草稿；
- 账本仍为 0；
- 两笔金额、日期和商户精确；
- 逐笔确认后账本净变动为 `-175.15`。

### F-05 退款、缺字段和未知模板

预期：

- 明确退款进入收入候选；
- 缺少金额或日期时整封进入隔离；
- 分期、撤销、手续费、账单汇总或外币模板未被确定支持时不得猜测写账。

### F-06 重复扫描

步骤：使用不同 UID 再次返回完全相同的 RFC822 内容。

预期：SHA-256 消息指纹命中重复；不增加第二组草稿或账本事件。

### F-07 UID 增量与上限

预期：只搜索 `last_uid + 1` 后的 UID，每轮最多 50 封；检查完成后推进游标，未命中白名单的邮件也不在下一轮重复扫描。

## I. 桌面关键用户旅程与对抗性仿真

以下用例必须在独立 bundle id `com.beizi.folio.e2e` 和独立数据目录中执行，不得触碰正式 Folio 数据。

### I-01 首次创建、锁定与错误密码

预期：创建后只持有会话句柄；锁定后快照读取失败；错误密码无法解锁且不会改变任何账本记录；正确密码可恢复原快照。

### I-02 全量冷启动与重复导入

预期：9 账户、7 持仓、26 流水、9 事项、1 规划按依赖顺序逐项确认；同一完整快照在已有数据上不能直接追加第二份账户或余额，只能选择“仅新增变化”或“重新录入全量数据”。

### I-03 日常增量、取消与错误金额

预期：合法增量先建草稿再确认；只创建未确认草稿时余额不变；`0`、负数、指数写法、三位小数和不存在账户均失败关闭，流水数和余额不变。

### I-04 流水修订与重复冲销

预期：修订追加反向事件和替代记录，原记录保留且标记已冲销；账户净额按差额变化；重复修订或冲销同一原记录失败关闭。

### I-05 持仓估值不重复计入

预期：追加持仓估值只改变账户内产品表现，不改变账户余额、净资产或历史账本；估值历史增加且旧估值不可变。

### I-06 周期事项完成本期

预期：只完成当前 occurrence；历史次数加一，并从原日历锚点推进下一期；不得删除原事项或重复创建资产/流水。

### I-07 规划与模拟隔离

预期：规划修改可确认并留痕，但不得改变账户余额、持仓或流水。

### I-08 清空后重新录入

预期：错误密码不能清空；正确密码清空后旧快照不可读；重建空白数据并重新确认完整快照后，账户数、持仓数、流水数、事项数、规划和净资产与原完整快照一致。

### I-09 七模块桌面渲染

预期：总览、资产、流水、规划、提醒、AI 管家、安全设置在真实 Tauri WebView 中逐页渲染；页面标题、核心数据区和主要操作入口存在；最后回到总览。

### I-10 桌宠与录入条锚定

预期：桌宠低优先状态仅显示局部动作，并从黑色录入条后方自然探出；尾巴位于绿色 AI 图标和文字之间，不得遮盖绿色图标、文字或麦克风，不得露出硬切底边，不得与录入条之间出现可见缝隙。移动端不加载桌宠，减少动态模式使用静态透明资源。
