# Folio 移动优先 MVP

> 版本：1.0
> 状态：当前实施基线
> 更新：2026-07-29

## 1. 一句话目标

让用户在手机上随时把一段语音、一张财务截图或一份已有资料交给 Folio；Folio 在保护隐私的前提下整理、归类并生成待核对项，用户确认后才更新账户、流水、事项或规划。

Mac 端复用同一套领域和数据能力，主要承担批量整理、对账、备份与恢复。MVP 不再同时追求完整云同步、外部 AI、多平台商店发布和复杂投资分析。

## 2. MVP 必须完成的四条路径

### 2.1 安全进入

- 首版必须支持应用密码创建和解锁。
- Touch ID、Face ID 或 Android 生物识别是便利层；不可用时必须能回退到应用密码。
- 锁定状态不展示金额、账户名、流水或通知正文。
- 短暂的系统权限弹窗或原生焦点切换不能造成解锁后立即误锁。

### 2.2 冷启动导入

无数据时，首页优先提示以下入口，而不是先展示复杂的空仪表盘：

1. 口述当前账户、余额、持仓和近期事项。
2. 选择财务截图或 PDF。
3. 选择 Markdown / 纯文本摘要。
4. 进入手动账户或表格导入。

推荐 Markdown 结构：

```md
# 账户
- 招商银行工资账户，余额 8600 元

# 持仓
- 工资账户内的沪深 300 基金，市值 1520 元

# 近期流水
- 2026-07-28 日用品支出 368 元，来自日常账户

# 事项
- 2026-08-02 缴保险 12800 元，提前 3 天提醒
```

输入不要求严格遵循模板。AI 可以识别自然语言，但金额、账户、日期、币种或动作不确定时必须要求用户补充，不能猜测。

### 2.3 日常 AI 录入

移动端底部中央保留单手可达的“AI 录入”，打开统一收件箱：

- 语音：Apple 设备优先强制设备内识别；不保存原始音频。
- 截图 / PDF：设备内提取文字；不保存原件和完整路径。
- Markdown / 文本：本机读取；原文只在本次解析和加密证据中使用。
- 直接文字：用于快速补充或修正。

统一处理链：

```text
输入
→ 提取文字与来源证据
→ AI 拆分并归类
→ 待核对提案
→ 原生领域草稿
→ 用户明确确认
→ 追加式账本或对应模块
```

首版支持归类到：

- 账户
- 持仓 / 产品操作
- 收入、支出和转账流水
- 财务事项
- 配置规划

一段输入含多个动作时，必须拆成多个待核对项；任何一个项目的失败不能悄悄改写其他项目。

### 2.4 信用卡邮箱账单

首个连接器按 QQ 邮箱设计，后续再抽象到其他邮箱。

- 使用 IMAP 专用授权码，不保存 QQ 登录密码。
- 连接器只执行搜索与读取，不执行标记、移动或删除。
- 用户选择专用文件夹、允许的发件人或信用卡通知规则；不扫描无关邮件。
- 本地仅保存消息标识、来源哈希、必要的脱敏证据和解析结果，不保存完整邮箱。
- 使用 `Message-ID + 正文规范化哈希 + 卡片尾号 + 金额 + 时间` 去重。
- 自动拉取和解析只产生“待核对流水”，绝不直接写入正式账本。
- 退款、撤销、分期、外币、预授权、重复通知和账单汇总必须单独识别；不确定时进入人工核对。

## 3. 还需要补齐的关键能力

除了用户已提出的语音、截图、Markdown 和邮箱，MVP 还需要：

- 待核对收件箱：集中显示来源、置信度、重复提示和未决字段。
- 一次输入多记录拆分：例如一张账单截图含五笔交易。
- 账户匹配与去重：同一卡片尾号、相近商户、同金额同时间不能重复入账。
- 对账状态：区分“已记录”和“已与账单/余额核对”。
- 修正能力：已确认流水通过冲销或修订事件更正，不直接覆盖历史。
- 离线队列：网络不可用时仍可语音转文字、本机识别和创建草稿；邮箱同步恢复后再继续。
- 隐私控制：每种来源明确显示是否离开设备、保留什么、如何断开。
- 失败关闭：币种、金额、账户或日期不明确时停止在待核对状态。

## 4. 里程碑

### M0 — 范围收口与移动主流程

状态：本轮完成

- 移动端冷启动改为语音 / 文档优先。
- 底部中央入口统一为“AI 录入”。
- 语音、截图 / PDF、Markdown / 文本和直接输入汇合到同一核对流程。
- 保留密码解锁；生物识别作为可选回退层。

### M1 — 多记录 AI 收件箱

状态：下一步

- 一次输入拆分多条账户、流水和事项提案。
- 增加持久化的待核对列表、来源证据和重复状态。
- 支持批量确认、逐条修改和逐条拒绝。
- 移动端完成空状态、错误态、离线态和恢复态。

### M2 — QQ 邮箱信用卡通知

状态：待实施

- QQ 邮箱 IMAP 授权码连接。
- 专用文件夹 / 发件人白名单和增量游标。
- 信用卡通知解析、去重、退款与撤销识别。
- 只写入待核对收件箱；确认后才创建流水。
- 断开授权、清除本地游标和隐私说明。

### M3 — 原生移动包与设备验收

状态：受工具链约束

- 初始化 iOS 工程并完成真机密码解锁、后台锁定、语音、相册 / 文件权限与本地数据库验证。
- 生物识别在有条件时接入；密码路径必须先通过。
- Android 在 iOS 主路径稳定后复用同一领域契约。
- 不在真机验证前宣称已有可安装的移动正式包。

### M4 — Mac 同步完善

状态：并行进行

- Mac 复用统一 AI 收件箱和 Markdown 支持。
- 保留批量 CSV/XLSX 导入、对账、备份、恢复和导出。
- 修复阻塞真实使用的问题，不新增非核心分析模块。

## 5. MVP 不做

- 不代替用户付款、转账或交易。
- 不让 AI 未经确认直接修改真实资产。
- 不保存网银或邮箱密码。
- 不把真实数据、令牌、数据库或私有文件提交到 GitHub。
- 不为首版同时建设完整的 Supabase 同步、Web 私人端、所有邮箱服务商和应用商店发布。
- 不把“自动读取邮箱”描述为“自动记账”；首版只自动生成待核对项。

## 6. 验收标准

- 新用户能在 3 分钟内通过口述或 Markdown 生成第一批待核对项。
- 用户能在手机宽度下完成密码进入、AI 录入、核对、确认和锁定。
- 截图、PDF、Markdown 和文本原件不会被写进仓库、日志或未加密缓存。
- 未确认、低置信度、重复或缺字段记录不进入余额和现金流。
- 同一来源重复导入不会生成第二笔正式流水。
- QQ 邮箱连接上线时，断开授权后停止拉取，且历史本地账本不受影响。
