## 已完成

### 原生工程

- 使用官方 Tauri 2 CLI 将现有 React/Vite 应用初始化为 macOS 原生工程。
- 应用标识为 `com.beizi.folio`，产品名为 `Folio`。
- 使用最终 Folio 品牌源图生成 macOS、iOS、Android 全套应用图标。
- 生产 WebView 配置显式 CSP；开发环境 CSP 仅开放本地 Vite 地址。
- 原生命令通过 `invoke_handler` 显式列出，未启用 shell 插件。
- Rust stable 1.97.1、Cargo 1.97.1 和 rustfmt 已安装。

### 安全数据基础

- 金额解析拒绝 JavaScript 浮点输入，统一转换为整数最小货币单位。
- 追加式账本支持原子批量写入、幂等键、冲突拒绝和冲销事件。
- AI/语音/导入结果使用 `needs_review` 草稿；没有明确确认不能写入账本。
- CSV/TSV/XLSX 在 Rust 内存中解析，支持字段映射、SHA-256 来源指纹、逐行错误报告和对账汇总；原文件或粘贴正文不落库、不进日志。
- 飞书 Sheet/Base、Excel 与 Numbers 已支持用户主动粘贴带表头单元格；应用不读取系统剪贴板，生成审核草稿后立即释放前端原始文本。
- 导入限制为 10 MB、5,000 行、64 列和单格 1,000 字；XLSX 只接受真实格式并读取首个工作表。
- 有效行与错误行分离；同文件重复外部流水号、错误日期/金额/类型和账户币种不一致会在核对页按行跳过。
- 用户明确确认后，有效行才在单个 `IMMEDIATE` 事务中写入账本、导入批次和审计；任何正式写入失败都会整体回滚。
- 相同正文以来源指纹和解析器版本幂等去重，即使改名或重复点击也不会再次增加余额。
- SQLite schema 包含 vault、account、import、draft、ledger、reminder 和 audit 实体。
- SQLite trigger 禁止原地更新或删除 `ledger_events` 和 `audit_events`。
- 应用锁状态机支持启动锁定、后台锁定、空闲超时和失败指数退避。
- 前端只保留原生 session handle，不接收数据库解密密钥。
- SQLCipher 以 vendored 方式编译，普通 SQLite 文件不是可接受的降级路径。
- 每个保险库生成独立随机 256 位 DEK；应用密码经 Argon2id 派生 KEK，仅用于封装 DEK。
- DEK 使用 XChaCha20-Poly1305 和保险库上下文 AAD 封装；密码与明文 DEK 不写入元数据。
- 原生 `vault_create`、密码 `vault_unlock`、`vault_lock` 和加密快照读取已接通。
- 连续 5 次解锁失败触发 30 秒原生冷却；错误密码、错保险库上下文和篡改密文均拒绝。
- Touch ID 能力由 LocalAuthentication 预检，DEK 条目写入 Data Protection Keychain。
- Keychain 条目使用 `AccessibleWhenPasscodeSetThisDeviceOnly` 与 `BIOMETRY_CURRENT_SET`；设备密码取消或指纹集合变化后不可继续释放该条目。
- 启用 Touch ID 仍需先验证保险库密码；未启用、无已登记指纹或系统认证取消时安全失败关闭。
- Argon2id、SQLCipher 和系统认证调用运行在后台阻塞任务，不冻结 WebView 主线程。
- React 原生入口可创建保险库，并支持应用密码或已登记 Touch ID 解锁。
- 原生应用启动时先清理遗留会话，再读取本机保险库列表；Web 构建不调用原生命令。
- 解锁后只通过 `vault_get_snapshot` 读取当前加密保险库，不以演示数据填充真实模式。
- 窗口失焦、应用进入后台或连续空闲 5 分钟会调用原生锁定，并卸载 React 中的快照和 session handle。
- 原生工作区提供安全设置状态页；除 AI 管家外，各模块均保留上下文语音入口，语音结果明确进入核对草稿。
- macOS 原生语音入口已接通 AVAudioEngine + Speech：逐次同意、仅解锁状态、强制设备内识别、最多 30 秒、单任务互斥；不保存原始音频，离线模型不可用时不联网降级。
- 安全设置新增本机系统通知控制：默认只显示通用锁屏文案，标题模式需用户主动选择，金额、账户和备注永不进入通知。
- 原生通知按事项日期和提前天数在本地 09:00 排程；稳定哈希标识实现幂等替换，权限拒绝/撤销时取消全部派生任务而不改变事项。
- Touch ID 登记失败不会回滚已经安全创建的保险库；用户仍可进入工作区并使用应用密码，界面显示可恢复提示。
- 安全设置现已提供 Touch ID 后置管理入口；恢复后或首次跳过的用户可验证当前密码重新启用，也可验证密码后明确关闭。
- 启用/关闭命令只接受当前已解锁保险库；未确认、错误密码或锁定状态都不会调用 Keychain 或改变元数据。关闭不影响应用密码和 SQLCipher 数据。
- 安全设置已提供应用密码轮换：当前密码重新认证、新密码双次输入、不可恢复确认后，只重新封装同一随机 DEK；旧密码失效，真实账本余额、当前会话和 Touch ID 保持不变，并追加脱敏安全审计。
- 资产页“添加账户”已接通真实原生命令：填写信息只生成 `needs_review` 草稿，只有用户在核对页明确确认后，才在单个事务中写入账户、期初余额事件和审计记录。
- 账户确认支持幂等重试；取消或返回修改会拒绝旧草稿，未确认草稿不会进入账户表或余额视图。
- `vault_get_snapshot` 已返回真实账户和逐币种余额；界面不会把不同币种直接相加为净值。
- schema migration v2 为既有账户表补充加密备注字段，迁移记录可审计。
- 账户卡片已提供管理入口；资料编辑会生成 before/after 核对草稿，确认后只更新账户主数据，不修改余额、币种或历史账本。
- 账户更新确认会重新比对核对前快照；核对后发生变化时拒绝覆盖，确认重试保持幂等。
- 归档在草稿创建与确认事务中都重新检查余额和有效持仓数；非零余额或仍有有效持仓的账户被阻止，安全归档只设置 `archived_at`，历史账本和审计记录继续保留。
- 资产页已增加“持仓与产品”管理区，支持按账户和产品类型筛选，展示数量、成本、市值、收益额、收益率、估值日期和历史估值次数。
- 新增持仓和更新估值都执行“填写 → 核对 → 明确确认”；数量精确到 6 位小数，金额以整数最小货币单位处理，币种必须与所属账户一致。
- `holding_valuations` 只允许追加，不允许更新或删除；估值草稿绑定核对时的前一版本，并发变化会安全拒绝。
- 持仓是账户余额的内部明细，原生命令不写账本或账户余额；界面明确显示“不重复计入”，避免产品市值再次增加总资产和净资产。
- 加密备份、恢复检查和可移植 ZIP 已覆盖持仓及全部估值快照；明文导出新增 `holdings.csv` 与 `holding_valuations.csv`。
- 持仓管理已支持资料编辑和安全归档：编辑只允许名称、类型、脱敏尾号和备注，账户与币种锁定；归档在确认时同时复核资料及最新估值版本。
- 持仓卡片已增加“记交易”，支持申购、赎回、分红和费用的专用表单与复核页。内部申购/赎回只追加估值；外部结算原子写入双边转账；分红/费用分别写入结算账户收入/支出。
- 每次确认都会追加不可变 `holding_operations` 记录并重新校验最新估值；持仓操作关联流水不能从普通流水入口单独冲销。备份恢复清单和可移植明文导出均已覆盖产品操作。
- 最近产品操作提供专用补偿式冲销：原因必填，原操作永久保留；确认后原子追加反向产品操作、关联账本反向事件和必要的恢复估值。位置类操作只有在其结果估值仍为最新版本时可冲销，且同一原操作只能处理一次。
- 操作历史明确显示“已冲销/冲销记录”；加密备份保留不可变关联，可移植 `holding_operations.csv` 导出原操作、补偿操作与原因。
- 资产页新增有效/已归档/全部状态筛选。归档后产品不进入有效数量或市值拆解，但产品主数据、全部不可变估值和归档日期仍可追溯。
- 流水页已接通真实原生命令，支持收入、支出和同币种账户间转账的“填写 → 核对 → 明确确认”流程；未确认草稿不改变余额。
- 流水金额由 Rust 精确解析为整数最小货币单位，拒绝零值、负值、指数写法、超精度与越界输入。
- 收入和支出追加单边事件；转账在单个 `IMMEDIATE` 事务中追加共享关联 ID、金额等值反向的转出与转入事件。
- 流水确认支持幂等重试，取消或返回修改会拒绝旧草稿；无效或被拒绝的转账不会产生部分账本写入。
- `vault_get_snapshot` 已返回逻辑流水列表；双边转账合并为一笔展示并排除在收入、支出和净现金流汇总之外。
- 当前跨币种转账默认拒绝，等待显式汇率、费用、舍入与证据核对流程完成后再开放。
- 正式流水已提供独立管理入口；冲销与修订都先生成 `needs_review` 草稿，只有核对后明确确认才会改变余额。
- 冲销为每个原始事件追加等额反向事件，并使用 `reverses_event_id` 保留精确追溯；原记录继续显示为“已冲销”，但不再进入有效现金流汇总。
- 修订在单个 `IMMEDIATE` 事务中原子追加原记录的反向事件和更正后的单边或双边交易；任一步失败都会整体回滚。
- 修正确认支持幂等重试，并重新检查原交易、账户状态和既有冲销；已冲销交易、归档账户或并发变化不会被重复影响。
- 流水快照保留冲销/修订原因和替代关系；界面同时展示“已冲销”原记录与“修订后”有效记录，完整历史不被覆盖。
- 提醒页已从占位模块接通真实事项快照与原生命令；主操作统一为“添加事项”，不会生成或发送催租信息。
- 事项支持租金、保险、理财到期、还款、定投、闲置资金和自定义类型，可选关联账户、金额、提前提醒、月度/年度重复与加密备注。
- 周期事项现按“完成本期”处理：月度/年度事项追加不可变完成期次、自动推进下一期并重新安排通知；原始日期锚点正确覆盖月末与闰日。
- 新增、编辑、完成和归档均先创建 `needs_review` 草稿；确认在单个事务中更新事项、追加事项事件与不可变审计，确认重试保持幂等。
- 编辑、完成和归档在确认时重新比对核对前快照；并发变化会拒绝覆盖。归档只设置 `archived_at`，不会删除事项历史或审计记录。
- schema migration v3 为既有保险库补充事项备注、软归档字段，并扩展 `updated` / `archived` 事项事件。
- 流水页已提供 CSV/TSV/XLSX 文件选择、虚构模板下载和飞书/Excel 表格主动粘贴入口，完成“选择或粘贴 → 映射 → 预览 → 核对 → 明确确认”的两步弹窗。
- `vault_get_snapshot` 已返回最近导入历史；确认后展示有效行数、错误行数和来源状态，取消/返回会拒绝未确认草稿。
- 安全设置与锁屏页已接通完整备份恢复入口；导出需要当前应用密码重新认证和独立备份密码，前端不获得完整保存路径。
- 备份通过 SQLite Online Backup 生成一致性 SQLCipher 快照，再用 Argon2id + XChaCha20-Poly1305 对清单、随机数据库密钥和快照整体认证加密。
- 恢复检查覆盖容器认证标签、SHA-256 文件指纹、SQLCipher 完整性、清单计数和外键关系；检查阶段不安装或修改保险库。
- 明确确认恢复后只创建新保险库，不覆盖既有数据；数据库轮换新的随机 DEK 和新应用密码，Touch ID 默认关闭。
- `.folio-backup` 已加入仓库隐私忽略规则；错误密码、容器篡改、未确认恢复和已存在目标均安全失败关闭。

## 当前安全边界

当前 `Folio.app` 是包含真实加密保险库能力的原生调试包。Tauri 环境进入本地保险库模式；浏览器开发版仍默认使用独立的虚构演示数据。

- `vault_unlock` 已支持应用密码和已配置的 Touch ID；未配置时安全失败关闭。
- `vault_get_snapshot` 在锁定状态拒绝访问。
- 不存在用明文 SQLite 或演示数据假装真实保险库解锁成功的降级路径。
- 原生 UI 已支持账户、账户内持仓资料/归档与不可变估值、手动流水、正式流水冲销/修订、财务事项、CSV/TSV/XLSX 批量导入、飞书/Excel 主动粘贴，以及独立密码保护的完整备份恢复。
- 本机通知实现与系统授权已接线并通过自动化测试；首次授权弹窗和实际到点投递仍需在用户设备完成交互验收。
- 当前包只使用 ad-hoc/linker 签名，不可作为正式公开分发包。
