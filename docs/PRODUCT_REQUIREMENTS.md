# Folio 产品需求文档

> 版本：1.2 · 移动优先 MVP
> 状态：MVP 收口基线
> 更新日期：2026-07-29

## 1. 产品定义

Folio 是一个本地优先、可审计的个人财务驾驶舱。它帮助用户统一查看资产、流水、配置计划和财务事项，并通过 AI 降低录入、归类、对账和解释成本。

Folio 不代替银行、券商或保险机构执行交易。任何影响真实账本的语音、文件或 AI 结果，都必须经过“解析 → 核对 → 明确确认”后才能生效。

## 2. 目标与成功标准

### 2.1 产品目标

- 先形成一个移动端优先的日常录入体验，Mac 端从同一套代码并行承担批量整理、对账、备份与恢复。
- MVP 聚焦安全解锁、AI 统一录入、核对确认和可靠流水更新；私人 Web、生产云同步、复杂分析和商店分发不阻塞核心闭环。
- 用户可以导入真实数据，但真实数据、密钥和个人文件不会进入 Git 仓库。
- 资产、流水和事项的每次变化都能追溯来源、确认人和时间。
- 断网时仍可完成查看、手工记录、导入和核对。
- AI 负责抽取、解释和建议，不绕过用户确认修改资产。

### 2.2 首个正式版本的成功标准

- 用户可以从 DMG 安装并在重启后继续用应用密码或 Touch ID 解锁同一加密保险库。
- 用户可在 10 分钟内创建本地保险库并导入第一份 CSV/TSV/XLSX，或主动粘贴一段带表头的表格单元格。
- 常用页面在解锁后 2 秒内显示最近一次本地快照。
- 相同文件重复导入不会产生重复流水。
- 100% 的 AI 资产变更先进入草稿；未经确认的草稿不计入正式余额。
- 锁屏、切换账号或超过设定空闲时间后，敏感金额不可见。
- 仓库自动测试可以阻止常见密钥、真实数据库和私有导入文件被提交。
- 使用一份代表性的真实数据副本完成导入、对账、加密备份、恢复为新保险库和可移植导出验收；测试后安全清理副本。

### 2.3 移动优先 MVP 边界

MVP 必须包含：

- 手机宽度下可完成应用密码解锁、AI 录入、核对、确认和锁定；生物识别可用时作为便利层，应用密码始终可回退。
- Apple Silicon macOS 应用继续可用，并复用同一保险库、领域草稿和确认规则。
- SQLCipher 本地保险库、不可变账本、账户/持仓/流水/事项/规划和本机通知。
- 手工录入、语音、截图/PDF、Markdown/纯文本、CSV/TSV/XLSX、Numbers/Excel/飞书表格显式粘贴。
- 所有语音、文件和 AI 写入继续执行“解析 → 核对 → 明确确认”。
- 加密备份/恢复、标准明文数据导出、隐私提示和自动锁定。

以下明确不阻塞 MVP：

- iOS/Android 商店发布、移动端后台同步和全平台同时上线。
- 私人 Web 访问、生产 Supabase、多设备同步和设备撤销。
- 外部云模型、本地大模型、云转写、飞书 OAuth/API 连接和银行直连。QQ 邮箱只读连接按独立里程碑接入。
- Developer ID 公证不是用户本人内部试用的功能前置，但若要求无 Gatekeeper 警告地分发给其他 Mac 用户，则必须在发布前完成。

## 3. 用户与平台

### 3.1 核心用户

- 资产分散在多个银行、基金、保险和房产中的个人或家庭管理者。
- 希望使用真实数据，但对云端存储和第三方模型有较高隐私要求。
- 需要在电脑上集中整理，并在手机上随时查看或快速补充事项。

### 3.2 平台优先级

1. 移动端体验：日常密码进入、语音/截图/文档/文字录入、待核对和确认。
2. macOS：并行保留批量导入、对账、备份、恢复和设备内文件处理。
3. 原生发布：iOS 先完成工具链与真机验收，Android 随后复用同一领域契约；未验收前不宣称可安装。
4. Web：后续建设安全的跨设备访问；不依赖本地原生生物识别能力。

## 4. 核心功能需求

### 4.1 总览

- 展示净资产、总资产、总负债、活期可用和月度现金流。
- 展示数据更新时间、来源、待确认数量和对账状态。
- 支持隐藏金额；锁定后不得通过页面缓存再次显示。
- 所有汇总均来自已确认账本事件，草稿单独展示。

### 4.2 资产

- “+ 添加账户”必须打开账户表单，而不是仅提示操作成功。
- 账户字段包括机构、账户名称、账户类型、币种、期初余额、余额日期和备注。
- 支持新增、编辑、归档和对账；归档账户保留历史流水。
- 账户存在账本事件后不得直接修改币种；只有余额为 0 且不存在有效持仓的账户可以归档，确认时必须再次校验余额和持仓状态。
- 支持按机构、类别、币种、同步状态筛选。
- 支持在账户内登记基金、理财、证券、保险等持仓/产品明细，并按账户和产品类型筛选。
- 持仓数量最多保留 6 位小数，成本与市值使用整数最小货币单位；新增持仓和更新估值都必须经过核对与明确确认。
- 每次估值更新追加不可变快照，展示成本、市值、收益额、收益率、估值日期和来源；不得原地覆盖历史估值。
- 持仓资料支持编辑产品名称、类型、脱敏尾号和备注；所属账户与币种在已有估值后不可直接迁移。
- 持仓归档必须经过独立核对并在确认时复核产品资料和最新估值版本；归档只从默认有效列表和市值拆解中移除，不删除产品或估值历史。
- 资产页支持有效、已归档和全部状态筛选；已归档持仓保持只读可追溯。
- 持仓是账户余额的内部拆分，市值不得再次计入总资产或净资产。申购、赎回、分红和费用都必须生成独立、不可变的产品操作记录，并经过“填写 → 核对 → 明确确认”。
- 账户内部申购/赎回只追加持仓估值快照，不改变账户总余额；选择外部结算账户时必须原子写入金额相等、方向相反的双边转账。分红写入结算账户收入，费用写入结算账户支出。
- 产品操作确认时必须重新校验最新估值版本。由产品操作生成的账本事件不得从普通流水入口单独冲销，避免账本余额与持仓快照脱节。
- 已确认产品操作提供专用“冲销”入口：原操作永久保留，用户填写原因并核对后，系统追加反向产品操作、必要的反向账本事件和恢复估值；同一原操作只能冲销一次。
- 申购/赎回只有在其结果估值仍是当前最新估值时才可冲销；后续已有估值时安全拒绝，避免覆盖后续持仓历史。冲销草稿在确认前发生任何持仓或流水变化时必须作废重建。
- 展示持仓表现、AI 配置建议和与真实资产明确隔离的模拟沙盘。

### 4.3 流水

- 支持收入、支出、转账、申购、赎回、分红、费用和余额调整。
- “+ 记一笔”打开与交易类型匹配的表单。
- 账户间转账生成关联的双边记录，不重复计算收入和支出。
- 大额、重复、余额不守恒和低置信度记录进入核对队列。
- 每笔正式流水保留原始来源、导入批次和修订历史。

### 4.4 规划

- 展示当前配置、目标区间、集中度和现金安全垫。
- 规划配置采用“生成核对草稿 → 明确确认”，目标占比必须精确合计 100%。
- 规划创建和更新保留不可变事件历史；并发过期草稿必须拒绝。
- 建议只能生成分析结果、待办或模拟方案，不自动发起交易。
- 模拟沙盘只存在于当前页面内存，不连接账本写命令；若用户希望采用方案，必须重新录入并明确确认规划草稿。

### 4.5 提醒

- 主操作统一为“添加事项”，打开事项表单。
- 事项支持租金、保险、理财到期、还款、定投和自定义类型。
- 字段包括标题、关联账户/资产、金额、日期、提前提醒、重复规则、备注和状态。
- 月度/年度事项的“完成”表示完成本期：系统必须保留不可变的本期完成记录并自动安排下一期；一次性事项才进入最终已完成状态。月末和闰日必须按原始日期锚点推进。
- 支持完成、延期、忽略和恢复。
- macOS/iOS/Android 可在用户明确授权后创建本机系统通知；默认锁屏只显示通用提示，不显示账户、金额、备注或事项标题。
- 用户可主动切换为“显示事项标题”，但金额、账户和备注在任何通知模式下都不得出现；Web 端不得把浏览器通知冒充生物识别或保险库解锁。
- 事项日期按本地时区在到期日减去提前天数后的 09:00 排程；已错过的时间不补发即时通知，避免解锁后集中弹出。
- 生成沟通文案只能作为事项详情中的辅助能力，不能作为提醒页主流程。

### 4.6 AI 管家

- 支持语音、文本、图片、PDF、Markdown、纯文本、CSV 和 XLSX 输入。
- Apple 桌面/移动端的图片、可选中文本 PDF 和扫描 PDF 默认在设备内识别；无文字层页面由 PDFKit 逐页渲染后交给 Vision OCR。原件与完整路径不进入前端、数据库、日志或同步。
- 默认可使用完全本地的中文规则解析账户、收入、支出、转账、财务事项、规划和产品操作；未覆盖的动作必须明确提示“不支持”，不得猜测成其他账本事件。
- 产品语音必须匹配唯一现有持仓和单一操作。申购/赎回还必须从原话中取得操作后份额、累计成本与当前市值；缺少任一精确值时只提示补充，不能推算或生成草稿。未说结算账户时，仅可按明确提示的持仓内部操作处理。
- macOS/iOS 原生端优先使用 Apple 设备内语音识别：每次录音前明确同意，强制离线识别，不保存原始音频；设备或语言不支持离线模型时安全拒绝，不得静默上传。
- Web 或未来云端语音服务若可能发生网络传输，必须另行说明接收方、用途和保留策略并获得本次明确同意；不同意时保留文字输入和系统听写路径。
- 结构化结果必须显示原始证据、字段置信度和不确定项。
- 金额、币种、账户、日期或动作存在歧义时必须要求用户修正。
- AI 回答资产变化问题时应引用对应账本事件和数据时间。
- 本地只读问答支持本月/上月收支比较、支出分类、金额最大支出和现金流解释；聚合回答必须显示来源覆盖率。“大额”不等于“异常”，不得在没有风险证据时暗示欺诈。
- 用户可选择“不发送个人数据到云模型”；此模式下只使用本地规则或已配置的本地模型。

### 4.7 全局输入

- Web 桌面端侧边栏除 AI 管家外，每个模块都提供上下文语音输入按钮。
- 语音按钮按当前模块生成对应草稿，例如账户、产品操作、交易、计划或事项。
- 移动端语音入口位于持久底部导航中央。
- 语音识别完成后只能进入核对页，不能直接改变真实资产。
- AI 管家使用页面内的主输入入口；其余桌面侧边栏模块保留右下角上下文语音入口，避免重复按钮。

### 4.8 数据导入与导出

- 第一阶段支持手工录入、CSV/TSV/XLSX、飞书 Sheet/Base 主动粘贴和本地备份。
- 导入流程为选择来源、字段映射、预览、重复检测、用户确认、写入和对账报告。
- 从飞书 Sheet/Base、Excel 或 Numbers 导入时，只处理用户主动粘贴的带表头单元格，不申请或后台读取系统剪贴板；粘贴内容按 TSV 在本机解析。
- 第一阶段只在本机内存中读取原始文件或粘贴正文，生成审核草稿后立即释放前端原始缓冲，不另存原件；后续如提供原件归档，必须由用户显式开启并加密保存。
- 支持导出标准 CSV、加密完整备份和审计日志。
- 标准导出以 ZIP 包含 UTF-8 CSV：账户、原始追加式账本、事项、规划、导入批次和可选审计事件；用户文本必须防止电子表格公式注入。
- 明文导出前必须重新验证当前应用密码，并要求用户明确确认未加密风险；保存时使用私有权限和原子写入，不静默覆盖既有文件。
- 完整备份使用独立备份密码；导出前重新验证当前应用密码，恢复前验证容器、数据库和数据关系。
- 恢复默认创建新保险库并轮换数据密钥，不覆盖、合并或删除设备上的既有保险库。

### 4.9 邮箱账单收件箱

- 第一连接器以 QQ 邮箱为目标，使用 IMAP 专用授权码；应用只执行搜索与读取命令，不保存邮箱登录密码。
- 用户主动选择专用文件夹、允许的发件人或信用卡通知规则；系统不得读取与财务无关的邮件正文。
- 自动拉取和解析只能生成待核对流水，不能直接写入正式账本。
- 使用消息标识、规范化正文哈希、卡片尾号、金额和时间做幂等去重。
- 退款、撤销、分期、外币、预授权和账单汇总必须区分；低置信度或字段缺失时停留在待核对状态。
- 断开授权后立即停止拉取并清除本地授权码/游标；已经确认的本地账本不受影响。

## 5. 身份、解锁与隐私需求

### 5.1 三层安全状态

- 身份登录：确认云端账号身份，使用密码或通行密钥。
- 应用解锁：确认当前设备操作者，使用 Touch ID、Face ID、Android 生物识别或设备密码。
- 数据解密：使用设备安全存储中保护的数据密钥打开本地保险库。

### 5.2 平台要求

- macOS / iOS：优先使用 Touch ID 或 Face ID，失败后允许应用密码恢复。
- Android：优先使用系统 BiometricPrompt，失败后允许应用密码恢复。
- 已解锁设备的安全设置允许重新认证后启用或关闭生物识别；恢复保险库时默认关闭，但不要求重建保险库才能重新启用。
- 启用与关闭均需当前应用密码和明确确认。关闭只删除本设备生物识别钥匙串条目，不删除保险库、应用密码或历史数据。
- 已解锁用户可在重新验证当前密码后设置不同的新应用密码；必须重复输入并确认已妥善保存。修改只轮换密码封装材料，不重写真实账本，Touch ID 保持可用，独立备份密码不随之改变。
- Web：优先使用通行密钥 WebAuthn，并提供密码登录；必须运行在 HTTPS 或本地开发环境。已登录页面连续 15 分钟无活动时立即退出本地会话并卸载私人数据界面。
- 应用启动、从后台恢复或空闲超时后按用户设置重新锁定。
- 连续失败触发指数退避；不得在日志中记录密码、生物识别信息或解密密钥。

### 5.3 数据模式

- 本地模式（原生默认）：真实数据只保存在当前设备的加密数据库中；普通浏览器不得打开或模拟原生保险库。
- 加密同步模式（可选）：经用户开启后同步到云端；服务端实施行级权限，账户、账本、事项、持仓资料、估值、产品操作及补偿更正正文全部在客户端认证加密，云端只保留最小路由元数据和密文。
- 跨设备恢复必须按账户 → 持仓 → 估值 → 账本 → 产品操作 → 补偿更正 → 事项的依赖顺序应用；缺少依赖、同标识不同内容或并发资料修改进入本机加密冲突区，不能部分写入或静默覆盖。
- 冲突核对必须在原生层重新验证哈希、AAD 和认证密文后才向已解锁用户展示必要的解密字段；第一版只允许用户明确“保留本机”，并追加不可变解决记录。采用远端内容必须先生成对应领域草稿并重新走核对/确认链，不能把同步冲突按钮变成账本写入捷径。
- 已登记设备列表只显示平台、登记/最近活动时间、状态和不透明设备 ID。设备撤销属于高风险操作，开放前必须具备近期重新认证、同步密钥轮换、其他有效设备重新包装和恢复路径验证。
- Web 锁定模式（Web 默认）：未明确配置安全访问模式时不渲染任何账户、流水、事项或 AI 数据，不得自动降级为演示。
- 演示模式：只加载仓库内的虚构数据，适合开发、截图和公开演示；必须通过显式非密钥开关启用、由访问者确认边界，并在整个界面持续标注“公开虚构演示”。

## 6. 非功能需求

- 金额使用整数最小货币单位，不使用二进制浮点数记账。
- 正式账本使用追加事件；修正通过冲销或后续事件完成。
- 写操作具有幂等键，导入任务可安全重试。
- 本地数据库、备份和临时解析文件均需加密或及时清理。
- 生产日志默认脱敏；不得记录访问令牌、文件正文或完整账户号。
- UI 满足键盘操作、清晰焦点、语义标签和基础对比度要求。
- 数据层不依赖 React 组件，桌面、移动和 Web 复用同一领域契约。

## 7. 明确不做

- 首个正式版本不保存网银密码，不使用模拟登录或网页爬虫。
- 首个正式版本不代替用户买入、卖出、转账或支付。
- 不承诺 AI 给出收益保证或个性化投资结论。
- 不把 GitHub、浏览器本地存储或普通明文文件当作真实数据主库。
- 不在前端保存 Supabase service role、AI 服务端密钥或数据库管理密钥。

## 8. 发布验收

一个版本只有在以下证据齐全时才可发布：

- 功能验收：核心路径有自动测试或人工验收记录。
- 数据验收：导入幂等、账本平衡、草稿隔离和备份恢复通过。
- 安全验收：锁定、鉴权、权限隔离、密钥扫描和日志脱敏通过。
- 平台验收：目标平台完成签名构建；macOS 正式版完成公证。
- 隐私验收：用户能够理解数据存放位置，并能导出和删除自己的数据。
