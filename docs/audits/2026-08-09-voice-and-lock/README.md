# Folio 解锁、桌宠与语音录入审查

## 范围

桌面端从解锁进入工作台后的会话保持、桌宠与录入条的连接关系、AI 管家输入焦点态，以及语音录入到实时转写的主路径。

## 步骤与结果

1. **工作台空状态（修复前：需改进）**  
   `01-overview.png` 证明右下桌宠和录入条由两个固定定位层组成；原始纵向定位保留了可见空隙。默认 5 分钟空闲锁也会在用户阅读或演示时意外打断主任务。

2. **AI 管家输入焦点（修复前：需改进）**  
   `02-assistant-focus.png` 证明输入框获得焦点后出现独立紫色矩形框，破坏了白色圆角输入条的一体感。

3. **语音输入（修复前：高摩擦）**  
   `03-current-voice-modal.png` 只有授权行、普通按钮和大文本框。没有明显的录音中心、声波反馈或实时识别状态；用户无法判断系统是否正在听，也无法边说边核对。

4. **语音输入（修复后：健康）**  
   `04-updated-voice-modal.png` 使用中央圆形麦克风、声波、明确的录音状态和下方实时文字区；仍保留逐次设备内授权和解析前人工校对。

5. **AI 管家输入焦点（修复后：健康）**  
   `05-assistant-focus-fixed.png` 保留光标与输入能力，移除额外紫框，输入条形态不跳变。

6. **冷启动猫爪（修复后：健康）**  
   `06-paw-anchor-fixed.png` 猫爪从录入条后方进入并与条体重叠，视觉上成为同一个锚定组件。

## 可访问性与证据边界

- 麦克风按钮、实时转写和录音状态都有可读名称；实时状态使用 `aria-live`。
- 减少动态效果偏好下会关闭波形与麦克风脉冲动画。
- 截图只能确认可见层级、焦点外观和控件名称；真实麦克风权限、声级变化和设备端部分结果还需在打包后的 macOS 应用中验证。
