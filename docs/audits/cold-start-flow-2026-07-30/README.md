# Folio 冷启动流程审计

审计日期：2026-07-30  
范围：空保险库 → 资料选择 → 本地解析 → 原生核对 → 明确确认 → 首页更新。

## 总体判断

单条“创建首个账户”已走通；整份 Markdown 的多领域批量拆分与批次确认尚未实现，因此全量冷启动仍是 P0 阻点。

## 步骤

1. **空保险库总览 — 健康**
   - 证据：`01-empty-workspace.png`
   - 优点：空状态、0 金额、导入入口和手动入口清晰；没有用模拟数据伪装真实状态。
   - 风险：桌面首屏下方的冷启动卡片需要轻微滚动才能完整看到，移动端需继续单独复核。

2. **资料选择 — 健康**
   - 证据：`02-document-capture.png`
   - 优点：语音、截图/文档、文字入口统一；文件不保存、不上传的边界明确。
   - 风险：当前 4000 字限制需要在批量导入摘要中明确展示截断状态。

3. **旧解析结果 — 已修复**
   - 证据：`03-single-proposal-blocker.png`
   - 问题：空库总览中的“添加账户”被误判为收入流水，并因没有账户而停止。
   - 修复：空库且出现明确账户意图时，优先生成账户提案。

4. **首个账户提案 — 健康**
   - 证据：`04-first-account-review-fixed.png`
   - 优点：机构、名称、类型、余额和日期都可核对；低置信度日期有明显提示。
   - 风险：内部枚举仍显示 `cash`，后续可统一显示“活期账户”以减少技术词。

5. **原生最终核对 — 健康**
   - 证据：`05-native-final-review.png`
   - 优点：明确区分模型提案和原生 SQLCipher 草稿；最终写入需要第二次确认。
   - 风险：截图只能证明可见状态，键盘顺序和读屏语义仍需专项测试。

6. **首条数据写入 — 健康**
   - 证据：`06-first-account-injected.png`
   - 优点：首页金额、账户数和账户列表立即更新，正式账本写入成功。
   - 风险：只验证了单账户。账户、持仓、流水、事项和规划的整批导入仍未完成。

## 最高优先级建议

1. 为 `folio_import_version: 1` 增加结构化 Markdown 批量解析器。
2. 增加分领域批次核对、依赖排序和失败恢复点。
3. 让演示文档一次完成全量注入，再进行移动端同流程复核。

## 证据限制

- 本轮使用开发预览中的虚构数据，不代表真实 Tauri 文件选择器和 SQLCipher 文件导入已经完成整批验收。
- 截图不能证明完整键盘访问、读屏体验、设备权限和应用退出后的行为。
