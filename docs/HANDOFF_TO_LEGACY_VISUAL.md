# Folio 旧版视觉线交接

更新时间：2026-07-30

## 决策

- 后续前端以旧窗口中 `http://localhost:4173/` 的版本及用户提供的移动端截图为视觉基线。
- 不继续在当前 `5173` 版本上做整页视觉回退，也不要直接合并当前分支的 `src/App.jsx`、`src/NativeVaultApp.jsx`、`src/main.jsx`、`src/styles.css`。
- 新功能应只替换旧版中对应的组件或状态，保留原页面结构、卡片层级、密度、间距、字体与视觉节奏。

## 可直接复用

### 冷启动与演示数据

- `docs/demo/Folio_冷启动全量演示数据.md`
  - 全部为虚构数据。
  - 覆盖账户、持仓、流水、提醒、配置规划、QQ 邮箱样例与异常场景。
  - 用作“空系统 → 文档导入 → AI 解析 → 分模块复核 → 明确确认”的演示输入。
- `tests/demo-cold-start-document.test.mjs`
  - 校验文档的虚构标记、字段覆盖、持仓金额、规划比例与邮箱安全样例。

### 可独立移植的小型逻辑修复

- `src/ai/localProposal.js`
  - 空系统在“总览”上下文也能识别首个账户，不再误判为收入。
- `tests/local-ai-proposal.test.mjs`
  - 新增上述冷启动首账户回归测试。

建议只摘取这一处小型 diff 和对应测试，不要整文件覆盖旧版。

### 产品与安全方案

- `docs/COLD_START_EMAIL_MVP_CHECKLIST.md`
  - QQ 邮箱采用专用文件夹 + 发件人/主题过滤 + 只读 IMAP + 授权码。
  - 邮件记录只进入待复核箱，绝不直接写入正式账本。
  - 包含移动端 MVP 的 P0/P1/P2 缺口清单。
- `docs/audits/cold-start-flow-2026-07-30/`
  - 保留空系统、捕获、复核、确认和首账户注入的验证截图与结论。

## 不应直接复用

- 当前 `5173` 线的整页布局、卡片结构、字号和导航改造。
- `src/App.jsx`
- `src/NativeVaultApp.jsx`
- `src/main.jsx`
- `src/styles.css`
- 任何仅为当前视觉审计生成的临时素材或页面结构。

如果其中包含需要的业务事件或状态管理，应按功能点人工摘取，不做整文件合并。

## 旧窗口接续顺序

1. 固定旧版视觉基线并留存桌面、移动端截图。
2. 先实现“空数据模式”和一键重置演示保险库。
3. 接入 Markdown 文档选择与整文解析。
4. 生成账户、持仓、流水、提醒、规划五类待复核草稿。
5. 分组复核并明确确认后，按依赖顺序写入本地账本。
6. 再接入统一 AI 收件箱（文字、语音、截图/PDF）。
7. 最后接 QQ 邮箱只读同步；先支持手动同步，再支持应用运行期间的每日同步。

## 验收边界

- 真实数据不得写入 Git。
- 所有金额变更都必须经过“解析 → 复核 → 明确确认”。
- 邮件、语音、文件原文只作临时证据，不直接成为已确认账本。
- 旧版视觉的还原度优先于新增装饰或整页重构。
