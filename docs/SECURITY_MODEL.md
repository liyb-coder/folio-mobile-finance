# Folio 安全与隐私模型

> 版本：1.0  
> 更新日期：2026-07-27

## 1. 安全目标

- 未解锁设备、其他云用户、代码仓库访问者和普通日志读取者不能获得用户财务明文。
- 被篡改的导入文件、重复请求或 AI 幻觉不能静默改变正式余额。
- 用户丢失设备或退出产品时，可以恢复、导出或彻底删除自己的数据。
- 安全机制失败时默认拒绝访问，而不是退回明文存储。

## 2. 保护对象

- 账户、余额、流水、保单、租约、附件和个人备注。
- 本地数据库、备份、同步事件、解析临时文件和缓存。
- 密码派生材料、数据加密密钥、会话令牌、AI/API 密钥和签名密钥。
- 审计日志、导入来源、设备列表和恢复材料。

生物特征模板不属于 Folio 数据：它始终由操作系统管理，Folio 只接收成功、失败或取消结果。

## 3. 信任边界

| 边界 | 默认信任 | 控制 |
|---|---|---|
| React UI | 不持有长期密钥 | 短期会话、输入校验、自动锁定 |
| Tauri Rust 层 | 允许访问解密后的最小数据 | 命令白名单、参数校验、最小文件权限 |
| 操作系统安全存储 | 信任系统保护 | Keychain/Secure Enclave/Keystore |
| Supabase | 不默认信任财务明文 | RLS、客户端加密、私有 bucket |
| AI 提供商 | 不默认信任个人数据 | 本地优先、最小披露、用户授权 |
| GitHub / CI | 公开或团队可见 | 只提交代码和虚构数据、密钥扫描 |

## 4. 主要威胁与控制

| 威胁 | 控制 |
|---|---|
| 真实数据被提交到 Git | 精确 `.gitignore`、独立私有目录、提交前自动扫描、只保留虚构 fixture |
| 设备丢失 | 整库加密、系统安全存储、自动锁定、远端会话撤销 |
| 恶意网页脚本读取数据 | CSP、依赖审计、最小 Web 缓存、敏感操作重新认证 |
| Web 数据模式误配后暴露演示或私人界面 | Web 默认 `locked`；`demo` 必须显式启用并先确认边界；浏览器 `local` 安全拒绝，三条路径都不得回退加载财务快照 |
| 已登录 Web 页面长期无人看管 | 15 分钟真实活动计时器；超时先在 UI 本地退出并卸载私人界面，再尽力撤销云会话，网络失败也不得恢复显示 |
| 其他云用户越权 | 所有业务表 RLS、跨用户否定测试、服务端密钥隔离 |
| AI 误写资产 | AI 只能创建草稿，用户逐项确认，账本追加与可冲销 |
| 口述被错误理解或错误路由 | 本地解析展示逐字段置信度和证据；缺金额、账户、日期或动作时阻止生成领域草稿；产品申购/赎回还必须明确结果份额、成本和市值，多个持仓或复合动作安全拒绝；原生层再次按草稿类型校验 |
| 语音或口述意外发送到外部服务 | Apple 原生端逐次同意并强制设备内识别，不支持离线模型时安全拒绝；Web/云端路径必须独立披露并同意。Folio 不保存原始音频，当前口述证据不进入同步 |
| 麦克风被并发或后台滥用 | 只有已解锁保险库可调用；3–30 秒上限、单任务原子门、录音期间禁止关闭核对窗；包内用途说明和音频输入 entitlement 显式声明 |
| 图片/PDF 原件或路径泄漏 | 原生文件选择与设备内 PDFKit/Vision 解析；限制类型、魔数、10 MB 和 50 页；React 只接收文字、指纹和证据坐标，原件/完整路径不落库、不记日志、不进入同步 |
| 恶意或超大文档耗尽资源 | 类型扩展名与魔数双校验、10 MB、PDF 1–50 页、单页 RGBA 受限渲染、最多 4000 字和 80 个前端证据块；逐页 OCR 后立即释放位图 |
| AI 提案被篡改或绕过确认 | `ai_proposals` 在 SQLCipher 中不可变并绑定同类型 `needs_review` 草稿；AI 命令没有确认或账本写权限 |
| AI 问答编造财务事实或泄露问题 | 本地问答只执行确定性只读计算，必须返回来源 ID 与数据时间；无引用时明确拒绝推测，问题只保存在当前解锁页面状态 |
| 持仓市值重复计入净资产或历史估值被覆盖 | 持仓被定义为账户内部拆分，原生命令不写账本或账户余额；估值只追加不可变快照，确认时校验前一估值版本，过期草稿安全拒绝 |
| 持仓资料并发覆盖、归档遗漏历史或悬挂在已归档账户 | 编辑比较完整 before/after 资料快照；归档同时校验资料与最新估值 ID，只设置 `archived_at`；账户归档前后都要求有效持仓数为 0 |
| 申购/赎回导致资产重复计入，或产品流水被单边冲销 | 内部操作不改变账户余额；外部结算只写平衡双边转账；分红/费用显式写入收支；操作、估值和账本在同一事务确认，并阻止普通流水入口单独更正持仓关联事件 |
| 产品操作冲销覆盖后续估值、重复生效或只恢复一侧 | 只允许专用补偿式冲销；位置类原操作必须仍对应最新估值；原操作、反向操作和原因由一对一不可变关联表连接，账本反向事件与恢复估值在单个 `IMMEDIATE` 事务中追加 |
| 手动流水重复或部分写入 | 草稿幂等确认、单事务写入、不可变账本与审计事件 |
| 转账破坏余额守恒 | 同币种双边事件共享关联 ID、金额等值反向并原子提交 |
| 流水修正重复、只冲销一半或覆盖历史 | 必填修正原因、原始快照复核、`reverses_event_id` 唯一约束；双边冲销及“反向 + 替代”在单个 `IMMEDIATE` 事务中幂等提交 |
| 未定义汇率造成静默损失 | 跨币种转账默认拒绝，必须先建立显式汇率、费用与舍入核对流程 |
| 事项误删或并发覆盖 | 草稿前后快照、确认时并发复核、软归档、事项事件与不可变审计 |
| 提醒被误解为外发催收 | 提醒附着于事项；主流程只记录和管理事项，不生成或发送对外文案 |
| 周期事项完成覆盖历史 | 每期完成记录追加到不可变 occurrence 表；确认草稿、本期日期和下一期日期一并留痕，禁止更新或删除 |
| 锁屏通知泄露财务隐私 | 默认固定通用文案；标题模式需用户主动选择；金额、账户、币种和备注永不进入系统通知或请求标识 |
| 通知权限撤销后仍残留排程 | 每次解锁和事项确认幂等核对系统权限；拒绝/撤销时取消所有派生请求，不影响加密事项事实 |
| 重复解锁造成重复通知 | SHA-256 稳定请求标识与每事项唯一派生行；原生同标识替换，未来排程上限 50 |
| 导入重复或篡改 | SHA-256 正文指纹、外部 ID、解析器版本、逐行幂等键、确认时复核与对账报告 |
| 恶意或超大表格耗尽资源 | 仅接受 CSV/TSV/真实 XLSX；10 MB、5,000 行、64 列、单格 1,000 字限制；只读首个工作表，不执行宏、公式计算或外部链接 |
| 剪贴板被静默窥探 | 不调用后台剪贴板读取能力、不申请剪贴板权限；只处理用户在可见文本框中主动粘贴的单元格 |
| 导入正文残留或外泄 | 原生进程内存解析、不落临时明文文件、不记正文日志；创建草稿后立即释放前端文件或粘贴缓冲，取消草稿不写账本 |
| 日志或崩溃报告泄密 | 字段级脱敏、禁记正文与密钥、用户可关闭遥测 |
| 本地插件或命令滥权 | Tauri allowlist、命令参数验证、不开放任意 shell |
| 密码暴力尝试 | Argon2id、指数退避、失败审计、设备级锁定 |
| 未授权修改 Touch ID 设置 | 仅当前已解锁保险库可操作；启用/关闭都重新验证应用密码并要求明确确认；错误只返回脱敏状态 |
| 未授权或半完成的密码轮换 | 仅已解锁保险库可调用；重新验证当前密码、限制失败次数、要求不同的新密码与明确确认；元数据原子替换，审计失败恢复旧封装 |
| 关闭 Touch ID 误删保险库 | 只关闭元数据开关并删除本设备 Keychain 条目；密码包装 DEK、SQLCipher 数据和历史记录不变 |
| 指纹集合变化后旧授权继续有效 | Keychain 条目绑定 `BIOMETRY_CURRENT_SET` 与设备密码保护；指纹集合变化后系统使旧条目失效 |
| 备份泄密 | 独立备份密码；Argon2id + XChaCha20-Poly1305 认证加密整个容器；外层不暴露保险库名称或金额 |
| 恶意备份耗尽资源或绕过校验 | 128 MB 容器/96 MB 数据库上限、固定 KDF 参数、SHA-256 指纹、SQLCipher 完整性和外键检查 |
| 恢复误覆盖或降级安全 | 只创建新保险库、目标存在即拒绝；恢复后轮换随机 DEK、新应用密码重新封装、Touch ID 默认关闭 |
| 同步密文被篡改、换类型或跳过前序事件 | AAD v2 绑定事件种类与路由元数据；SHA-256 覆盖 AAD/nonce/ciphertext；原生层认证解密并检查设备内逻辑时钟前序哈希 |
| 资产事件先于依赖到达或只恢复一半 | 固定账户 → 持仓 → 估值 → 账本 → 产品操作 → 补偿更正 → 事项的发送和应用顺序；每个引用重新校验保险库、币种和关联对象；缺依赖时隔离事件且不创建草稿或业务记录 |
| 第二设备把刚恢复的数据重复回传形成事件风暴 | 入站正式写入追加 `incoming_applied` 审计；outbox 跳过没有后续本机确认审计的入站事实，仅同步设备上新产生的变更 |
| 多设备编辑静默互相覆盖 | 账户、持仓资料和提醒维护设备版本；不可变估值/操作比较完整语义；相同内容幂等，跨设备分歧或标识碰撞进入 SQLCipher 冲突区并要求显式核对 |
| 冲突详情被替换、篡改或成为绕过确认的写入口 | 每次查看都从不可变 inbox 重新验证哈希、AAD 和认证密文；前端只接收必要解密字段。第一版只允许明确保留本机并追加不可变解决/审计记录；采用远端必须另走领域草稿核对链 |
| 设备列表泄漏财务信息或误撤销导致数据不可恢复 | 列表只返回平台、时间、状态和不透明 ID，并要求当前内存身份及 vault 作用域；撤销写操作在近期重新认证、密钥轮换、其他设备 rewrap 和恢复演练完成前保持关闭 |

## 5. 密钥与恢复

- 每个保险库拥有独立随机 `DEK`，设备只保存经包装的密钥。
- 应用密码不得直接作为数据库密钥；使用 Argon2id 派生包装密钥。
- 更改应用密码只用新的随机盐、Argon2id KEK 和 nonce 重新包装同一 `DEK`，不重新加密整个数据库；Touch ID Keychain 中仍是同一 DEK，独立备份密码不受影响。
- 注销设备应删除该设备包装密钥和会话；必要时轮换同步密钥。
- 恢复材料不得自动上传到与数据相同的账号而不做额外保护。
- 已导出的加密备份可在忘记原应用密码时使用独立备份密码恢复为新保险库；遗忘备份密码仍无法恢复。

## 6. 会话与锁定

- 默认启动即锁定；用户可配置短暂后台宽限时间。
- 系统锁屏、用户切换、手动锁定和敏感密钥失效立即锁定。
- 锁定时清除内存中的 `DEK`、访问令牌和可识别数据快照。
- 查看恢复密钥、导出完整备份、关闭加密或删除保险库必须重新认证。
- Web Auth 会话只保存在页面内存，不写入 Web Storage；刷新页面需重新登录。连续 15 分钟无指针、键盘、触摸或窗口聚焦活动时先本地退出并卸载私人界面，再尽力撤销云会话。

## 7. 数据生命周期

```text
采集 → 受控临时区 → 草稿 → 确认账本 → 加密备份/可选同步
         ↓ 过期清理       ↓ 拒绝后清理
```

- 临时明文只保留完成解析所需的最短时间。
- 删除账户默认归档；非零余额或仍有有效持仓的账户不得归档，归档后仍保留账本与审计历史；彻底删除保险库需要明确二次确认。
- 云端删除包括数据库行、对象存储、设备会话和计划任务。
- 备份保留策略由用户选择，并明确说明历史备份可能仍包含已删除记录。

## 8. 仓库规则

允许提交：

- 源代码、schema、迁移、文档、虚构演示数据、脱敏测试 fixture。

禁止提交：

- `.env`、真实数据库、真实 CSV/TSV/XLSX/PDF、导入缓存、`*.folio-backup`、访问令牌、service role、AI 密钥、签名证书。

`VITE_*` 变量全部视为公开配置。Supabase publishable/anon key 可以用于客户端，但真正安全边界必须来自 RLS；service role 和 secret key 永不进入前端。

Web 同步身份客户端使用非持久会话：访问令牌与刷新令牌只存在于当前页面内存，不写入 `localStorage` 或 `sessionStorage`。这会牺牲刷新页面后的自动登录便利，但降低 XSS 后长期令牌被持久窃取的暴露面；未来若改用服务端 HttpOnly Cookie，必须单独完成 CSRF、会话撤销和部署边界评审。

macOS 同步设置复用同一非持久身份策略：云端令牌只存在于当前解锁工作区的 Supabase 客户端内存，React 状态只接收用户 ID/邮箱的安全投影，不接收令牌或同步密钥。云端身份登录不会自动启用上传；启用和停用各自要求显式勾选确认。首次远端 bootstrap 失败时，本机配置补偿回滚为关闭；停用只停止此设备上传/下载，不把“停止同步”误表述为已删除云端密文。

Tauri WebView 网络边界由 CSP 继续限制：生产 `connect-src` 允许本机 IPC 与 Supabase 的 HTTPS/WSS 子域，不允许任意 `https:`、`wss:` 或第三方 API。专属 Supabase 项目建立后，发布门应把通配子域收紧到实际项目 host，并验证 Auth、REST 与 Realtime 所需连接仍然可用。

云端密文事件的可见元数据被限制为同步所需最小集合：保险库/设备/事件 UUID、粗粒度事件种类（账户、持仓资料、估值、账本、产品操作、补偿更正或事项）、逻辑时钟、幂等键、哈希链、密文长度及时间。账户名称、持仓名称、金额、数量、市值、币种、备注、标签、事项正文和附件元数据不得作为可查询明文字段上传。客户端加密不能隐藏访问频率、时间、对象大小、事件种类和设备关系，这些剩余泄漏在隐私说明中必须明确披露。

原生设备密钥对与保险库同步密钥保存在 SQLCipher 内，仅在保险库已解锁的原生进程中使用；前端命令响应不包含私钥或对称密钥。新增设备通过 X25519 共享秘密、HKDF-SHA256 和 XChaCha20-Poly1305 获得设备专属包装 envelope。后续移动端正式版应进一步将设备私钥迁移到 Secure Enclave/Keychain 或 Android Keystore，并保留应用密码恢复路径。

本机同步冲突采用证据与决议分离的追加模型：`sync_inbox_events`、`sync_inbox_conflicts` 和 `sync_inbox_conflict_resolutions` 均保留历史，处理动作不会删除密文或冲突。用户查看冲突时原生层重新执行认证解密，React 不接收 nonce、ciphertext 或密钥；明确保留本机只拒绝应用该入站事件并写审计。发送侧核对保持只读，接受远端保持关闭，直到领域草稿适配器能保证同等的并发复核与明确确认。

本地 AI 提案原文和字段证据属于敏感财务数据，只保存在已解锁保险库的 SQLCipher 中。审计日志不复制正文；取消的领域草稿不影响正式汇总。若未来接入云转写或云模型，必须在调用前展示提供商、发送字段、保留策略和本次授权，并允许用户继续使用完全本地路径。

设备内文档识别同样遵守 AI 草稿边界。原件只在原生进程的清零缓冲中短暂读取；PDFKit/Vision 结果经过长度和证据数量限制后才返回页面。确认草稿时保存的是 SQLCipher 内的提取文字、文件 SHA-256、页码/范围和可选坐标，不保存原件二进制或完整路径。用户修改提取文字会解除文件证据关联，避免修改后的文本被错误标记为原件证据。

可移植 CSV 导出是用户主动创建的明文副本，不继承 SQLCipher 或备份密码保护。导出前必须重新验证保险库密码并明确确认风险；原生层使用私有文件权限、临时文件 `fsync` 和原子改名，拒绝覆盖已有文件。成功审计只记录 SHA-256 指纹、大小、选项和计数，不记录用户选择的目标路径。用户界面必须持续提示不要将此文件提交到 GitHub、公开网盘或群聊。

本地账本问答与写入提案使用不同能力边界：`local_ledger_qa_v2` 只接收只读快照，没有 repository、Tauri 命令或草稿确认句柄；问题、指标和回答在锁定时随 React 工作区卸载。跨期分析只汇总未冲销的基础币种收支，明确排除转账和无汇率币种；“大额”只做排序，不自动判定异常。引用只显示当前用户已经解锁可见的对象，并同时给出来源覆盖率，不创建新的跨设备数据副本。

## 9. 安全发布门

- 密钥与隐私文件扫描无高风险发现。
- 数据库文件、WAL、备份和临时文件的静态检查无财务明文。
- 锁定后无法通过 UI、缓存、日志或应用切换预览恢复金额。
- RLS 跨用户测试全部通过。
- 备份恢复演练成功，错误密码和篡改备份均被拒绝。
- Tauri 命令清单、依赖、CSP、签名和自动更新来源经过复核。
