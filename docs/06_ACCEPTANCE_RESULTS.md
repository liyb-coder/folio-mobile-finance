## QQ 邮箱连接器结果

已实现：

- QQ Mail/Foxmail IMAPS（TLS 993）；
- `EXAMINE` 只读打开邮箱，不删除、不移动、不发送、不标已读；
- 先读取 `From/Subject` 邮件头，命中发件人域名与主题关键词后才读取正文；
- 授权码只写 macOS Keychain；
- SQLCipher 只保存邮箱配置、UID 游标、消息 SHA-256、发件人域名和草稿关联；
- 完整邮件正文不持久化；
- 单封日结邮件拆分多笔消费；
- 退款识别为收入候选；
- 金额按整数分写入草稿；
- 重复消息指纹拒绝二次生成；
- 每笔都进入 `email_transaction` 待核对草稿，人工确认后才写账；
- 设置页提供配置、只读连接测试、读取新邮件、逐笔确认/拒绝和停用。

尚未完成：

- 没有用户 QQ 邮箱授权码，因此未执行真实账户登录；
- 不同银行邮件模板仍需用脱敏样本扩充；
- 分期、撤销、手续费、账单汇总和外币邮件仍应默认隔离；
- `imap 2.4.1` 的依赖会产生 future-incompatibility 警告，发布前需要评估升级到维护中的 IMAP 实现。

## AI Provider 结果

已实现：

- Rust 侧 OpenAI Responses API 网关；
- `store:false`；
- Strict Structured Outputs；
- API Key 优先读取显式环境变量，也可写入 macOS Keychain；
- 每次真实财务文字外发都需要当次明确同意；
- 返回证据必须是输入原文中的连续片段；
- 模型永远不能执行确认写账。

实网状态：

- 检测到 `OPENAI_API_KEY` 存在，但从未读取或输出其值；
- Rust、curl 和 Node 对 `api.openai.com` 均在连接阶段超时；
- 因此本轮只能确认实现、单元测试和失败关闭行为，不能把实网连接标记为通过；
- Codex 会话内部模型不是已安装 App 可直接调用的运行时 API，产品仍需显式模型 Provider。
