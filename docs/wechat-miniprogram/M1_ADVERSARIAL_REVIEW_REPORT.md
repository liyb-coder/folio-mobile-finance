## 对抗角色与结果

| 角色 | 攻击/误操作 | 门禁与结果 |
|---|---|---|
| 粗心用户 | 把演示金额当成真实数据 | 解锁页、顶栏和数据 fixture 均标记“虚构演示” |
| 连续点击用户 | 在 M1 反复点录音/上传/添加 | 只返回“下一里程碑接入”，不申请权限、不发网络请求、不写账 |
| 窃密者 | 从小程序包中搜索模型/服务凭证 | 源码扫描和回归测试拒绝凭证字段；DeepSeek 凭证只能从 BFF 进程环境读取 |
| 提示注入者 | 在财务原文中要求忽略系统指令或直接写账 | DeepSeek 提示将原文视为不可信证据，BFF 只输出 `pending_review` |
| 幻觉模型 | 伪造原文不存在的账户、金额或日期 | 每个 `evidenceQuote` 必须在原文中精确命中，否则整个提案 fail closed |
| 被篡改客户端 | 伪造 `confirmed` 或 `ledgerEventId` | 共享提案契约拒绝服务端管理字段和非 `pending_review` 状态 |
| 不稳定上游 | DeepSeek 返回 429、截断 JSON、空数组或错误详情 | BFF 使用稳定错误码，不传回上游详情或凭证，不产生草稿 |
| 审核者 | 要求证明本程序未隐藏真实网络与写入行为 | M1 源码门禁禁止 `wx.request`/upload/recorder/storage 和账本确认命令 |

## 已转为回归门禁的问题

1. 页面/资源漏包：新增每个本地 WXML 图片引用的包内存在性检查。
2. 根项目 ESM 与微信 CommonJS fixture 的测试加载冲突：测试器改用显式 CommonJS 沙箱加载，不修改小程序运行时格式。
3. 居中采集按钮的结构验证不稳定：将采集项显式渲染为独立 `capture-tab`，保留可访问名称和真实图标资源。

## 人工阻塞（不得伪装完成）

1. 当前 Mac 没有微信开发者工具，无法取得 WXML 编译和视觉截图证据。
2. 没有小程序 AppID、主体权限、体验成员与实名合规证据。
3. 当前进程不可见 `DEEPSEEK_API_KEY`，真实 API 不能执行；模拟上游通过不代表实网通过。
4. 手机不在身边，iOS 真机 DeepSeek BFF 、语音、文档和解锁冒烟按用户决定后置。
