# M2a 对抗式审查报告

更新：2026-08-12

## 对手模型

- 粗心用户：空输入、连点提交、网络中断后误以为已保存；
- 恶意输入：提示词注入、超长文本、伪造账户/金额指令；
- 幻觉模型：引用原文不存在的金额、返回空证据、夹带写入状态；
- 篡改客户端：将远端地址降级为 HTTP、伪造 confirmed；
- 不可靠服务：超时、非 2xx、残缺 JSON、重复项目 ID；
- 合规审查：客户端包搜索模型凭证、误导性“已自动记账”文案。

## 本轮发现与修复

1. **旧 M1 门禁把整个工程永久限制为只读。** 进入 M2 后它会误报合法的 BFF 请求。修复为仅约束 M1 展示面，并新增独立 M2 网络边界测试。
2. **客户端参数错误可能同步抛出，也可能异步拒绝。** 这会使页面异常处理不一致。将 API 固定为 async rejection，所有失败都走同一核对失败路径。
3. **模型返回 pending_review 并不等于可信。** 增加服务器管理字段、来源匹配、项目类型、项目 ID、证据来源与精确原文覆盖校验。
4. **没有真实身份时做“确认写入”会制造错误安全感。** 核对卡明确标识等待确认，最终写入按钮保持不可用，直到 M2b。
5. **测试服务地址可能诱导把密钥放进配置。** 运行时配置只保留空的公开 BFF 地址；DeepSeek 凭证仍只存在于服务端环境。

## 剩余风险

- 微信开发者工具尚未用真实 AppID 编译，WXML/CSS 仍缺实际视口证据；
- loopback BFF 只能用于本机开发，真机需要备案 HTTPS 域名；
- 未接入真实微信身份，提案暂时不能绑定用户或跨设备恢复；
- 未实现服务端提案版本和确认防重放，因此不能开放写账；
- 微信小程序语音如果使用云 ASR，隐私文案不能沿用 macOS 的“设备内转写”。
