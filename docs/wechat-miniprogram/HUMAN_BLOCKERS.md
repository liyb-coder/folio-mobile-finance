# Folio 微信小程序必须人工解决的堵点

状态：Open，2026-08-12

进展：微信开发者工具 2.02.2607271（Apple Silicon，Tencent 官方签名）已安装，CLI 服务端口已开启。H11 仍未完成，因为开发者工具尚未扫码登录，也没有真实 AppID、体验成员和真实测试设备证据。当前 `touristappid` 在新版工具中返回 code 10，不能据此声称已经编译或真机通过。

以下事项不能靠写代码自动完成。没有对应人工证据时，只能开发本地/fake 环境，不能声称可正式上线。

## A. 开发启动前必须决定

| ID | 人工事项 | 需要谁 | 完成证据 | 不解决的后果 |
|---|---|---|---|---|
| H01 | 确定小程序注册主体：个人、企业或其他组织 | 产品负责人/公司负责人 | 主体名称与证件 | 类目、接口和审核能力不确定 |
| H02 | 注册微信公众平台账号并取得 AppID | 主体管理员 | AppID、开发者成员权限 | 无法进入真实开发工具和体验版 |
| H03 | 确定服务类目与产品表述 | 产品+法务/合规 | 后台可选类目截图、资质结论 | “财务/理财”文案可能触发资质或拒审 |
| H04 | 决定数据部署地域和云供应商 | 产品+安全+法务 | 架构决策与区域 | 新加坡 Supabase 可能带来延迟/跨境评估问题 |
| H05 | 选择 ASR、OCR、LLM 供应商并购买正式凭证 | 产品+采购/财务 | 合同、API 额度、数据条款 | 无法提供真实语音/OCR/AI |
| H06 | 定义数据保留和删除策略 | 产品+隐私负责人 | 数据清单、TTL、删除 SLA | 隐私指引无法真实填写 |
| H07 | 确定桌面账户与微信身份的绑定方式 | 产品负责人 | 绑定交互和恢复策略 | 用户产生两套孤立财务数据 |

## B. 联调前必须完成

| ID | 人工事项 | 完成证据 |
|---|---|---|
| H08 | 购买并控制业务域名，配置有效 HTTPS/WSS 证书 | 域名和证书控制权 |
| H09 | 服务器与小程序/APP 备案 | 备案号或平台受理/通过状态 |
| H10 | 在微信后台配置 request/upload/download/socket 合法域名 | 后台域名配置截图 |
| H11 | 安装微信开发者工具，配置开发者、体验成员和最少两台真实测试手机 | 工具版本、成员清单、设备矩阵 |
| H12 | 准备真实但不含客户数据的测试账号与虚构财务样本 | 测试数据说明 |
| H13 | 在微信后台选择或申请提醒消息模板 | 模板 ID 与允许字段 |

工信部的应用备案范围包括小程序等分发形态，备案涉及主体、接入和平台协作，不能由代码代替：[工信部备案通知](https://www.miit.gov.cn/zwgk/zcwj/wjfb/tz/art/2023/art_920db564162e4312916a01bed6540ad8.html)。

## C. 提审前必须完成

| ID | 人工事项 | 完成证据 |
|---|---|---|
| H14 | 小程序名称、Logo、简介、服务类目、搜索词和审核截图 | 后台完整资料 |
| H15 | 用户协议、隐私政策、儿童/年龄政策、客服与投诉渠道 | 已发布可访问文本 |
| H16 | 隐私保护指引与代码实际权限逐项一致 | 隐私接口扫描无差异 |
| H17 | 账号注销、数据导出、数据删除的运营处理人和 SLA | 工单流程与负责人 |
| H18 | AI 输出显式标识、导出元数据标识和用户协议说明 | 法务确认与测试证据 |
| H19 | 是否需要算法备案、安全评估或其他生成式 AI 材料 | 法务/合规书面结论 |
| H20 | 财务文案和类目资质审查 | 法务/行业顾问结论 |
| H21 | 应急联系人、隐私联系人、数据泄露和错账事故流程 | 值班表与响应预案 |
| H22 | 管理员实名、扫码/人脸确认、提交审核和最终发布 | 管理员实际操作完成 |

《人工智能生成合成内容标识办法》已于 2025-09-01 生效，文本、图片、音频、视频等生成内容涉及显式/隐式标识，应用上线审核还可能核验相关材料：[国家网信办原文](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)。这部分需要法务判断 Folio 的“整理、摘要、建议、导出”分别适用什么标识方式，工程只能执行结论。

## D. Folio 特有的人工决策

### D1. 产品到底是“财务整理工具”还是“投资建议服务”

推荐首版明确为：记账、提醒、账户/持仓信息整理和用户控制的规划建议。不要出现自动投资、自动调仓、承诺收益、替用户决策等能力或文案。若要提供个性化证券/基金投资建议，必须先让具备资格的法律和行业人员判断业务资质，不能由开发团队自行解释。

### D2. 是否允许财务数据出境

当前 Supabase 默认区域为新加坡。面向中国大陆真实用户前，必须由负责人选择：

- 改用境内部署；或
- 完成跨境个人信息与供应商合规评估后继续；或
- 仅保存端到端密文，并验证路由元数据是否仍构成个人信息。

在结论前，开发只使用虚构数据和 provider-neutral adapter。

### D3. 语音是否承诺“设备内”

微信小程序没有当前 Apple Speech 的同等设备内边界。若使用云 ASR，产品文案必须改为“本次语音将发送至服务端转写”，并明确原始音频 TTL。不能沿用桌面端“不会上传音频”的承诺。

### D4. 提醒能否作为核心承诺

微信订阅消息需要用户授权，并可能因模板、系统通知、微信设置或用户拒绝而不可达。首版必须把应用内提醒作为系统记录，订阅消息只是增强，不得承诺必达。

### D5. 旧数据如何进入微信端

必须人工选择并设计：

- 桌面端显示一次性绑定码/二维码；
- 用户在桌面端已解锁状态下明确确认；
- 服务端建立微信身份与 Folio 账户映射；
- 首次同步前展示将同步的数据范围；
- 解绑不删除账本，删除账户需要单独流程。

## E. 建议负责人模板

| 角色 | 建议责任 |
|---|---|
| 产品负责人 | 范围、文案、类目、供应商、数据地域、上线批准 |
| 微信主体管理员 | 注册、实名、成员、模板、备案、审核、发布 |
| 隐私/法务 | 服务类目、财务边界、隐私、AI 标识、跨境、协议 |
| 技术负责人 | 架构、安全、域名、部署、测试、回滚 |
| 财务/采购 | 云和模型额度、合同、自动续费、预算告警 |
| 客服/运营 | 注销、删除、投诉、错账、事故响应 |

## F. 当前最先需要用户提供的五项

1. 小程序拟使用的注册主体；
2. 微信公众平台 AppID 或由谁负责注册；
3. 面向客户是否只定位“记账/提醒/财务整理”；
4. 是否接受境内云和正式模型 API 费用；
5. 是否要求小程序和桌面端使用同一份真实账户数据。
